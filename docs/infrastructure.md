## Future hosting (not approved)

The always-on Cloud Run worker-pool plan is withdrawn. Prefer:

1. **Request-driven Cloud Run** for the API (scale to zero).
2. **Event-triggered worker**: Cloud Scheduler (or a Postgres event) POSTs
   `/internal/worker/run`. One drain per wake. No min instances.
3. Or **reuse `automation-server`** only after a capacity check. Do not touch
   that VM until authorized.

Avoid: paid Neon upgrades, always-on compute, frequent idle `SELECT` polling of
Neon, Railway, new IAM breadth, production writes.

Database roles stay split: `agentping_migrator` (DDL, Alembic, direct URL) and
`agentping_runtime` (DML only, pooled URL, `prepare_threshold=None` for
PgBouncer). Recheck GRANTs when adding schemas.

## Environment

See `.env.example` and [configuration](configuration.md). Compose secrets are
generated by `python3 infra/compose_env.py` into ignored `.env.compose` and
`.env.compose.db` (mode 0600). The API container binds `0.0.0.0` inside Docker
and publishes `127.0.0.1:8000` on the host.

Image: `docker build -f backend/Dockerfile .` from the repo root so the root
`.dockerignore` excludes credentials, `.env.*`, Firebase configs and Android.

## Auth before production exposure

`AUTH_MODE=development` is refused when `APP_ENV=production`. Configure OIDC
(`OIDC_ISSUER`, `OIDC_AUDIENCE`, Android client id) first. Auth0 remains the
proposed provider.

## Operations checklist for a future deploy

- Separate production runtime/migration credentials (never the dev ones)
- Secret Manager per secret, attached service account, no JSON keys
- FCM send permission only on the worker identity
- Restricted package name = `com.errorfactory.agentping`
- HTTPS `PUBLIC_BASE_URL`, MCP allowed hosts/origins
- Worker trigger token, Scheduler job, no min instances
- Backup/restore plan for Neon; audit log retention
